Chapter 4 How Computers Remember Things

In the previous chapter, we went inside the CPU. We learned that the CPU is responsible for executing instructions, that it contains things such as registers and execution units, that it works with instructions defined by an instruction set architecture, and that modern processors use caches and multiple cores to get work done efficiently.

But there is one huge problem. The CPU needs information to work. Imagine you're doing a calculation: 25 + 75. The CPU needs the numbers 25 and 75.

If you're running a game, the CPU needs information about: your character, the position of enemies, your health, the current level, game physics, textures and other resources. If you're opening a web browser, the computer needs to keep track of: the browser's program, open tabs, web pages, images, JavaScript data, user input, temporary information.

So where does all of this information go? Does the CPU itself permanently remember everything? No. The CPU has extremely small amounts of very fast storage inside it, but computers need much larger places to hold information. That's where memory and storage come in.

And before we start, remember our rule: One step, not one kilometer. We're going to start with the smallest possible idea and build our way up.

1. What Does It Mean for a Computer to "Remember" Something?

When we say "The computer remembers something," we don't mean that the computer has a brain or memories like a human. We mean that the computer has a physical system capable of representing and retaining information.

For example, a computer might need to remember: Player Health = 87 or Score = 1250 or Username = Avaneesh or even an entire photograph. All of these things ultimately have to be represented using physical states inside the computer.

At the lowest level, digital computers work with binary states. Those states can be represented physically using things such as electrical charge, voltage levels, magnetic states, or other physical properties depending on the technology being used.

"The computer stored 87" really means: Some physical system was placed into a state that represents the information needed to represent the value 87. That's what computer memory fundamentally is — a system for representing and retaining information.

2. Bits — The Smallest Unit of Digital Information

In Chapter 1, we introduced the word: Bit. A bit is short for Binary digit. A bit can represent one of two possible values: 0 or 1.

One bit doesn't have enough possibilities to represent a huge amount of information. But it is incredibly important because computers can combine many bits together. For example: 

1 bit  →  2 possible states
2 bits →  4 possible states
3 bits →  8 possible states
4 bits →  16 possible states

The number of possible combinations doubles every time we add another bit. With 8 bits: 2⁸ = 256 possible combinations exist. Those combinations can represent values from 0 through 255 when interpreted as an unsigned 8-bit number. That's why 8 bits became such an important grouping in computing.

3. Bytes — Groups of Bits

A group of 8 bits is called a Byte. So 1 byte = 8 bits. For example, 01000001 is one byte. Depending on the encoding, that particular byte can represent the character A.

This is where things start becoming interesting. A byte doesn't inherently mean "A". It is simply a pattern of bits. Software decides how that pattern should be interpreted. The same bits could represent: a number, part of a text character, part of an image, part of an instruction, part of a sound file, or part of some other data.

Bits don't have meaning by themselves. Meaning comes from how software and hardware interpret them.

4. Why Can Computers Store Pictures Using Only 0s and 1s?

You might wonder: "How can a photograph possibly be represented using only 0 and 1?" After all, a photograph contains millions of colors. The trick is that computers don't need a special "photo language." They represent the information numerically.

For example, an image can be represented as a grid of pixels. Each pixel can have numerical values representing its color. A simple RGB pixel might contain: Red, Green, Blue. Each component can be represented using numbers. For example: R = 255, G = 0, B = 0 can represent bright red in a typical RGB representation. Those numbers themselves are stored as binary. 

Photo
 ↓
Pixels
 ↓
Color values
 ↓
Numbers
 ↓
Binary data
 ↓
Physical storage states

The computer doesn't need to "understand a photograph." It only needs to store and process the data representing it.

5. Everything Becomes Data

This idea becomes even more powerful when you realize that computers can represent almost everything digitally. Text? Data. Music? Data. Video? Data. A Python program? Data. A game? Data. A photograph? Data. Your operating system? Data. A PDF? Data.

At the hardware level, all of these are represented using patterns of bits. But don't misunderstand this as "Everything is just a random pile of 0s and 1s." There is structure. A file format tells software how those bits should be interpreted.

The bits are the raw representation. The format gives them meaning.

6. Memory Is Not the Same Thing as Storage

This is one of the most important distinctions you'll learn in this chapter. People often say: "My computer has 16 GB of memory." Sometimes they mean RAM. Other times people casually use "memory" to mean storage. Technically, these aren't the same thing.

A computer can have 16 GB RAM and 512 GB SSD. Those numbers describe completely different resources. RAM is primarily used as working memory while programs are running. An SSD is persistent storage used to retain data even when the computer is powered off.

RAM is somewhat like a desk where you're currently working.

Storage is somewhat like a cupboard where you keep things when you aren't actively using them.

The analogy isn't perfect, but it gives you the right starting point.

7. RAM — The Computer's Working Memory

Fig 4.1: RAM provides the computer with working space for active programs and data.

RAM stands for Random Access Memory. RAM is a type of memory that provides the computer with working space for active programs and data.

Suppose you launch a game. The game is stored on your SSD. But the CPU doesn't simply execute the entire game directly from the SSD. The operating system and other software load the required information into memory. 

SSD
 ↓
RAM
 ↓
CPU

The CPU then works with data made available through the memory system. For example, while your game is running, RAM may contain information related to: game code, current game state, objects, variables, loaded assets, operating-system data, and other active programs. This is why having more RAM can allow a computer to keep more active data available without constantly moving information elsewhere.

8. Why Is RAM Called "Random Access" Memory?

The word random here doesn't mean "The computer accesses random data." It means that the computer can access individual memory locations without having to read everything before them sequentially.

Imagine a huge apartment building. If someone tells you: "Go to apartment 850." you don't necessarily need to visit apartments 1 through 849 first. You can go directly to the relevant location. RAM works conceptually like this. Memory is organized into addressable locations. The processor can request data associated with a particular address.

Memory locations can be addressed individually. That's what makes random access useful.

9. Memory Addresses — Giving Data a Location

If RAM contains billions of bytes, how does the computer know where something is? Each addressable location has an Address. Think of memory like a gigantic row of numbered boxes. 

Address       Data

1000          42
1001          17
1002          91
1003          5
1004          200

If the CPU needs the data at address 1002, it can request that location. The numbers above are just an illustration. Real systems use much larger address values and specific addressing rules.

Address → Where

Data → What

This concept becomes extremely important when you later learn about pointers. A pointer is, roughly speaking, a value that can represent an address or location relevant to accessing data. We'll spend much more time on pointers when we reach programming fundamentals.

10. What Does "Random Access" Look Like in Practice?

Imagine memory containing: A, B, C, D, E, F, G, H. Suppose the CPU wants F. It doesn't need to read A, B, C, D, E before reaching F. It can address the location containing F. That's the basic idea behind random access.

This is different from some forms of sequential access, where reaching a later piece of information requires moving through earlier information first. The distinction is useful because it helps explain why different storage technologies behave differently. Different technologies have different access characteristics. And those differences matter to software performance.

11. RAM Is Volatile

Here's an important property of traditional system RAM: It is volatile memory. That means its contents normally disappear when power is removed.

Imagine opening a game and changing your character's position. That information can exist in RAM while the game is running. Then you shut the computer down. The contents of RAM are no longer retained in the same way. But the game itself is still installed. Why? Because the game was stored on persistent storage such as an SSD.

RAM → Temporary working memory

SSD → Persistent storage

This distinction is incredibly important. RAM is designed for active work. Storage is designed to retain information.

12. What Happens When You Turn Off Your Computer?

Let's follow the journey. Suppose you've installed a game. The game is stored on your SSD. You turn on the computer. The operating system starts. You launch the game. The system reads the required information from storage and places relevant data into memory. 

SSD
 ↓
RAM
 ↓
CPU

While you play, the CPU constantly processes data. The game state changes. Your character moves. Enemies move. The score changes. New data gets created. Some data gets removed. Some data gets written back to storage. Then you close the game. If the game saves your progress, information is written to persistent storage. Then you shut down the computer. RAM loses its contents. But the saved game remains on the SSD.

13. Registers vs RAM

We already learned about registers in Chapter 3. So now let's compare them. Registers are extremely small storage locations directly associated with CPU execution. RAM is much larger system memory used to hold active programs and data.

Registers → Extremely fast, Extremely small, Inside the processor

RAM → Much larger, Slower than registers, Main working memory

Imagine you're solving a math problem. The numbers you're currently using are written directly on the paper in front of you. That's somewhat like registers. The textbooks sitting on your desk are somewhat like RAM. And the books stored in another room are somewhat like persistent storage. The closer the information is to your immediate work, the faster it can generally be accessed—but the available capacity tends to be smaller.

14. Cache — The Middle Ground

Between registers and RAM, modern processors use caches. We introduced cache in Chapter 3. Now we can understand why it exists. Suppose the CPU repeatedly needs the same data. It would be inefficient to constantly retrieve it from farther-away memory if it can keep a copy closer to the processor. That's where cache helps.

Registers ⚡ Fastest, Smallest
L1 Cache
L2 Cache
L3 Cache
RAM
SSD / HDD 🐢 Largest, Slowest

Generally: Closer to the CPU = faster but smaller and Farther away = larger but slower. This is not a perfect rule for every detail of modern systems, but it is a useful mental model. The cache system tries to keep useful data close to where it will be needed.

15. Cache Hits and Cache Misses

Now let's introduce two important terms: Cache hit and Cache miss.

Suppose the CPU needs some data. If the data is already available in the relevant cache: Cache hit. Great. The processor can access it without going farther down the memory hierarchy. But if the data isn't there: Cache miss. The system has to look farther away. 

CPU asks for data
       ↓
Is it in cache?
   ↙       ↘
 YES       NO
 ↓          ↓
Use it    Look farther

This is one reason programs with good memory-access patterns can sometimes perform much better than programs that constantly jump around in memory. And yes, programmers can eventually learn how their code interacts with these systems. You don't need to optimize every Python program around cache behavior. But when you eventually work with lower-level languages and performance-sensitive code, this becomes extremely important.

16. SSD — Persistent Flash Storage

Fig 4.2: SSD storage — fast, durable, and no moving parts.

Now let's move farther away from the CPU. An SSD stands for Solid-State Drive. Modern SSDs commonly use flash memory to store information persistently.

Unlike RAM, flash storage retains information when the computer is powered off. This makes SSDs suitable for storing: operating systems, applications, games, photos, videos, documents, projects, and other files.

When you save a Python project, for example: 

my_project/
    main.py
    calculator.py
    README.md

those files can be stored on your SSD. When you turn the computer off: They're still there. That's the key difference between persistent storage and volatile working memory.

17. How Is an SSD Different From RAM?

Both RAM and SSDs store digital information. So why not use only one? Because they are designed for different jobs. RAM is optimized for fast working access during program execution. SSD storage is designed to retain large amounts of information persistently.

RAM SSD
Purpose Working memory Persistent storage
Keeps data without power No Yes
Typical capacity Smaller Larger
Speed Very fast Slower than RAM
Used while programs run Yes Yes, but mainly for loading/saving

This is why a computer can have 8 GB RAM and 512 GB SSD and there's no contradiction. The 8 GB and 512 GB are serving different purposes.

18. HDD — The Older Storage Technology

Fig 4.3: An HDD stores data using magnetic material on spinning platters.

Before SSDs became common, many computers used Hard Disk Drives or HDDs. An HDD stores data using magnetic material on spinning platters. A mechanical read/write head moves over the surface of the platters to access data. That means an HDD contains moving mechanical parts.

An SSD, by contrast, has no spinning disk or moving read/write head. This difference has major consequences. HDDs can offer large capacities at relatively low cost, but they generally have much higher access latency than SSDs.

  • SSD → Faster, Quieter, More resistant to mechanical shock, Smaller, More responsive
  • HDD → Larger capacities at lower cost, Slower, Mechanical parts can fail

But SSDs aren't simply "RAM but slower." They use fundamentally different storage technology and have different performance and endurance characteristics.

19. Why Does an SSD Feel So Much Faster?

Imagine opening a large application. With an HDD, the system may need to move mechanical components to access different areas of the disk. With an SSD, there are no spinning platters or mechanical heads to position. This dramatically reduces access latency.

That's why upgrading from an HDD to an SSD can make an older computer feel dramatically more responsive. For example: launching an application, opening files, booting an operating system, loading a game, and searching through files can all benefit significantly from the lower latency of SSD storage.

Storage speed is not the same as CPU speed. A computer is a system. Performance depends on many components and on what the workload is actually doing.

20. Why Can't We Just Make RAM As Large As an SSD?

This is a great question. You might think: "If RAM is faster, why not just put 2 TB of RAM in every computer?" There are several reasons. One is cost. Another is physical design. Different memory technologies have different characteristics involving: speed, density, cost, power, persistence, and manufacturing complexity.

Computers therefore use a hierarchy instead of one giant type of memory. You don't want every byte of data stored in the fastest possible memory. That would be enormously expensive and inefficient. Instead, computers keep the most immediately useful information in faster layers and larger amounts of information in slower layers. This is the same fundamental idea we saw with cache.

21. The Memory Hierarchy

Now we can finally see the larger picture. A simplified memory hierarchy looks like:

⚡ Registers — Fastest, Smallest
⚡ L1 Cache
⚡ L2 Cache
⚡ L3 Cache
RAM
SSD
HDD — Largest, Slowest 🐢

As we move downward:

  • Capacity generally increases.
  • Cost per bit generally decreases.
  • Access generally becomes slower.
  • Persistence changes depending on the technology.

Again, this is a simplified model. Real systems can have additional levels and complicated interactions. But this hierarchy explains a huge amount about how computers are designed.

Instead of asking: "Why doesn't the computer use one giant super-fast memory?"

You can now answer: "Because speed, capacity, cost, power, and persistence involve trade-offs." Computer engineering is full of trade-offs.

22. What Is Virtual Memory?

Now things get a little more interesting. Suppose your computer has 8 GB RAM but your programs collectively need more memory than is currently available. What happens? Modern operating systems can use a system called Virtual memory.

Virtual memory gives programs an abstraction of memory that is managed by the operating system and hardware. A program can operate within its own virtual address space rather than directly managing physical RAM addresses. The operating system and processor's memory-management hardware work together to translate virtual addresses into physical memory locations.

This gives the operating system much more control over memory. For example, one program generally shouldn't be able to simply access another program's memory whenever it wants. Virtual memory helps provide isolation and protection as well as enabling memory-management techniques that can use storage as backing when necessary.

23. Does Virtual Memory Mean "RAM on the SSD"?

People sometimes explain virtual memory as: "Using your SSD as extra RAM." That's a useful beginner shortcut, but it isn't the full story. Virtual memory is primarily an abstraction and memory-management system.

One of its mechanisms can involve moving memory pages between physical RAM and storage. When memory pressure becomes high, the operating system may write less-active pages to storage and later bring them back when needed. This is much slower than accessing RAM.

If your computer is constantly relying heavily on storage because physical RAM is insufficient, performance can become very poor. You might notice:

  • Applications becoming extremely slow
  • Disk activity becoming very high
  • The computer feeling unresponsive

That's one reason having enough RAM matters.

24. What Is a Page?

Virtual memory is often managed in chunks called Pages. Instead of thinking about memory as one enormous continuous block that the operating system moves around one byte at a time, imagine dividing it into many fixed-size pieces. 

Page 1
Page 2
Page 3
Page 4
Page 5
...

The operating system can manage these pages independently. A virtual address belongs to a virtual memory space. The hardware and operating system cooperate to determine where the corresponding physical data resides. Some pages may be in RAM. Some may be temporarily backed by storage. The details are more advanced, but this gives you the basic idea. This is one of the foundations behind memory management in modern operating systems.

25. Memory Protection — Why Can't Every Program Read Everything?

Imagine you open Calculator and Browser at the same time. You don't want the calculator program to freely read the browser's private memory. You also don't want a random application to simply overwrite important operating-system memory. That would be a disaster.

Modern systems therefore use hardware and operating-system mechanisms to enforce memory protection and isolation. Each process typically receives its own virtual address space. This means that two programs can use the same virtual address value while those addresses refer to different physical memory. 

Program A
Virtual address 1000
       ↓
Physical memory location X

Program B
Virtual address 1000
       ↓
Physical memory location Y

The number 1000 doesn't necessarily mean the same physical location for both programs. The translation system handles the difference. This is a huge part of why modern multitasking operating systems can safely run many programs simultaneously.

26. What Is a Pointer?

Now we're going to connect all of this to programming. Suppose your program has x = 42. At the programming-language level, you can think of x as a variable containing the value 42. But somewhere underneath, the computer has to represent that value in memory or in another storage location used by the runtime.

In languages such as C and C++, programmers can explicitly work with addresses using Pointers. For example, conceptually: 

int x = 42;
int* p = &x;

Here: x contains the value 42 while p contains an address associated with x. This is why understanding memory addresses matters. A pointer isn't simply "another variable." It represents a location relevant to accessing data.

Python hides most of these low-level details from you. And that's intentional. Python gives you a much higher-level abstraction. But eventually, understanding what's happening underneath will help explain why lower-level languages expose these concepts more directly.

27. Why Does Python Hide So Much Memory Management?

Consider this Python code: 

numbers = [10, 20, 30, 40]

You don't manually say: "Give me 32 bytes of memory." You don't manually calculate every address. You don't manually free the memory when you're done. Python handles a huge amount of this work through its runtime and memory-management system.

This is another example of abstraction. Python lets you think: "I have a list." instead of: "I have a particular arrangement of objects in memory with specific addresses and metadata." That makes Python easier to use.

Python programmers sometimes don't see the underlying costs immediately. For example, objects can consume more memory than a simple raw array of machine integers might. That's one reason learning the fundamentals underneath high-level languages is useful.

28. What Happens When You Open a Program?

Let's put everything together. Suppose you double-click your Python editor. Where is the program? It is stored on persistent storage.

 ↓
Application files

You launch it. The operating system loads the required parts into RAM.

 ↓
RAM

The CPU then fetches instructions and accesses data through the memory hierarchy. 

RAM

 ↓

 ↓
CPU

As the program runs, it creates and modifies data. Some of that data lives in memory. Some information may be read from storage. Some data may eventually be saved back to storage.

29. What Happens When You Save a File?

Let's say you've been writing your first Python program: 

print("Hello, World!")

While you're editing it, the program and editor are using memory. Your changes exist in the computer's working state. When you click Save, the editor writes the file to persistent storage. 

Your changes
     ↓
RAM
     ↓
Operating system
     ↓
File system
     ↓
SSD

Now the file exists persistently. You can shut down the computer. Turn it on tomorrow. Open the file. The information can be loaded from storage again. This tiny action—clicking Save—is actually another example of the entire computer system working together.

30. CPU + Memory + Storage — The Big Picture

We've now covered three of the most important parts of a computer:

CPU — Processes instructions and performs calculations.

Memory — Provides fast working space for programs and the data they are currently using.

Storage — Keeps programs and files even when the computer is turned off.

A simplified picture looks like this: 

                 PROGRAM
                    ↓
                 STORAGE
                    ↓
              ┌───────────┐
              │    RAM    │
              └─────┬─────┘
                    ↓
              ┌───────────┐
              │   CACHE   │
              └─────┬─────┘
                    ↓
              ┌───────────┐
              │ REGISTERS │
              └─────┬─────┘
                    ↓
              ┌───────────┐
              │    CPU    │
              └─────┬─────┘
                    ↓
               PROCESSING
                    ↓
             RESULT / DATA

This is obviously a simplified model. Real computers contain many more components and layers. But this model gives you an important foundation.

When you run a program, its files are stored somewhere on persistent storage. The operating system loads the required parts into memory, the CPU works with that information, caches keep frequently needed data closer to the processor, and the results can eventually be written back to memory or storage.

So when you write something as simple as print("Hello, World!"), there is a huge amount of hardware working underneath that one line. You don't need to understand every transistor or memory cell yet. The important thing is that you now understand the basic relationship:

Storage → Memory → CPU → Result

And this brings us to an interesting question. How did humans even get here? The computer sitting on your desk contains billions of transistors, multiple CPU cores, gigabytes of RAM, and enormous amounts of storage. But computers didn't start like this.

The first computers weren't thin laptops. They weren't smartphones. They didn't have colorful operating systems. Some weren't even electronic. So how did we go from simple mechanical calculating devices to the computers we use today? To answer that, we need to go backwards.

🎯 The Big Takeaway

A computer doesn't have one magical place called "memory." It uses a hierarchy of technologies, each designed for a different purpose.

⚡ Registers — Fastest
⚡ CPU caches
RAM
SSD / HDD — Largest, Slowest

The closer something is to the CPU, the faster it can generally be accessed, but the available capacity is usually smaller and more expensive. The farther away it is, the more information we can generally store, but access becomes slower.

And all of these technologies exist because computers are built around trade-offs. You now understand another important layer of the machine you're programming on.
