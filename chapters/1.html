Chapter 1 Introducing You to This Amazing but Complex World

When you enter the world of programming, you might think you just need to learn a programming language and immediately start earning thousands of dollars. But it's actually the opposite — when you learn a language, you also need to learn some libraries with it. A language cannot contain every specific feature you might need; you could build everything yourself, but that's months or even years of work. Since existing libraries exist, we prefer using libraries made by the community.

We also learn about version control systems such as Git (git-scm.com/about) so we can save each version of our code and every minor change. If we suddenly break something, we can safely roll back to an older version using our commits which act as saved snapshots of our project's history. There are also many more things such as PRs (Pull Requests), Issues, and many more, and we'll go into depth on all of them. Now let's stop overwhelming you and start the course!

1. What is Programming?

Programming is the process of creating a set of instructions that tell a computer or other machine how to perform a specific task or solve a problem. We create these instructions using specific programming languages, scripting languages, or commands.

A computer or CPU understands binary — code like 01010100 01101000 01101001 01110011 00100000 01101001 01110011 00100000 01100001 01101110 00100000 01100101 01111000 01100001 01101101 01110000 01101100 01100101 00100000 01101111 01100110 00100000 01100010 01101001 01101110 01100001 01110010 01111001 00100000 01100011 01101111 01100100 01100101 00101110 which translates to "This is an example of binary code."

2. What is Binary?

Fig 1.1: How human code is translated into machine code for the CPU

Binary is a number system that uses only two digits — 0 and 1 — to represent all data, text, images, and instructions.

These 2 digits can be understood by the CPU. Whenever we write code, a specific software such as a compiler or interpreter converts these human-readable instructions into machine code (0s and 1s), which can be executed and performed by the CPU (Central Processing Unit).

Think of it like this: Imagine you're giving directions to someone who only knows two words — "left" and "right." You'd have to break down every instruction into those two words. Binary is the same for computers. Every piece of data, from the text on your screen to the colors in a photo, is translated into a massive sequence of 0s and 1s.

The binary system is also used in digital circuits, where a 1 represents an "on" state and a 0 represents an "off" state. This is why computers are built with billions of tiny switches (transistors) — each one can be either on or off, representing a 1 or a 0.

Fun fact: The word "bit" comes from "binary digit." A group of 8 bits is called a byte, and bytes are the building blocks of all digital information. For example, the letter 'A' in binary is 01000001.

3. Why Don't CPUs Understand Programming Languages?

CPUs can't understand programming languages because they are physical pieces of hardware, not thinking minds. They are built out of billions of microscopic electronic switches that can only react to physical electricity. Because of this, English-like code such as if (x > 5) means absolutely nothing to a microchip.

To bridge this gap, software tools called compilers or interpreters act as translators, breaking our human-readable code down into a massive sequence of binary code — the 1s and 0s — that the hardware can actually execute.

Fig 1.2: Compiler vs Interpreter — two ways to translate code

When we say a computer reads 0s and 1s, it's actually just a metaphor — there are no numbers inside a chip, only electricity. A "1" simply represents high voltage (power on), and a "0" represents low voltage (power off). The CPU uses tiny electronic switches called transistors to control this power. By turning these switches on and off, the chip routes electricity through pre-wired channels that naturally calculate results, manipulate data, and run your programs based purely on the laws of physics.

4. What is a Programming Language & How Does It Work?

A programming language is a formal system of rules and syntax that lets you tell a computer what to do. Think of it like a language you speak to a robot — but the robot is extremely literal and cannot understand ambiguity.

Two Main Types of Programming Languages

  • High-Level Languages (Python, Java, JavaScript): Closer to English, easier for humans, need translation.
  • Low-Level Languages (Assembly, Machine Code): Closer to binary, harder for humans, faster for machines.

To convert your code into something the CPU understands, we use:

  • Compiler: Translates the entire program at once (C, C++)
  • Interpreter: Translates line-by-line as it runs (Python, JavaScript)

5. Psychopaths (The Great Devs)

Do you know that one compiler or interpreter is made in one language? For example, the C++ compiler was first written in C, and later the compiler compiled itself. But some psychopaths — or great devs, in respect — created the compiler of the very first assembler (the tool that processes assembly language) directly in binary (0s and 1s), also known as machine code.

These pioneers built the foundation that we all stand on today. Without them writing the first compilers in binary, we wouldn't have the high-level languages we use now. They weren't psychopaths — they were visionaries.
